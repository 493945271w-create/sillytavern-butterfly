# 蝴蝶效应 · 世界线记录

给 SillyTavern 的同人、沙盒聊天记录相对原著的重大分歧，并在下一轮生成前整理与当前场景有关的差异。

**0.3.0 试用版，面向 SillyTavern 1.18。** 分析模型独立配置，使用者填写自己的 API 地址、密钥和模型。支持 OpenAI 兼容的 **Chat Completions** 接口，可从服务读取模型列表，也可手填模型名。无需额外运行本地桥接服务。

正式分歧需要同时说明：原著情况、当前已确立的实质变化、已经改变的重要前提。普通日常不会因“原著没写过”就变成蝴蝶效应。没有变化的回合可以不产生新记录。

## 安装

下载发布包后，可解压到酒馆的 `data/<用户目录>/extensions/sillytavern-butterfly/`，确认这一层目录直接包含 `manifest.json` 和 `index.js`，然后刷新酒馆。

仓库发布后，也可在酒馆「扩展 → 安装扩展」中填写：

```text
https://github.com/493945271w-create/sillytavern-butterfly
```

刷新页面后，打开左下角「蝴蝶效应」，或在扩展设置里打开「世界线记录」。本仓库的 `manifest.json` 与 `index.js` 位于根目录，无须构建。

## 第一次使用

1. 打开「模型设置」，填写服务提供的 API 基础地址，例如 `https://你的服务地址/v1`，以及自己的密钥。
2. 点击「读取模型列表」后，在模型框选择或输入完整模型名。如果服务没有 `/models` 接口，可以直接填写。
3. 保存设置。默认不发送思考强度参数；服务明确支持 `reasoning_effort` 时，再选择低、中、高。部分模型需要把输出上限字段切换为 `max_completion_tokens`。
4. 打开目标聊天。需要原著对照时，在「参考资料」中粘贴当前阶段的原著片段、Wiki、时间线或其他设定，也可以从 TXT / Markdown 文件读入。标题请写清来源、版本和阶段。
5. 点击「启用当前聊天」，再点击「整理接下来的剧情」。第一次从最近 8 条消息开始，以后接着上次进度分批整理。
6. 点击「让模型整理发送对照」查看预览。确认内容合适后，勾选「将已核实的重大分歧加入下一轮生成」。

启用聊天后默认打开「回复后检查重大分歧」，默认关闭向正文发送。启用自动整理、手动整理、生成预览和发送前筛选会调用所选模型，费用按你自己的服务计费。

## 记录哪些变化

- 关键人物的生死、长期归属或阵营发生改变。
- 重要关系已经成立或结束；关键决定已经明确作出。
- 关键能力、物品或知识的归属，改变了重大事件的成立条件。
- 同一分歧有实质进展时，合并更新原条目，旧状态保留在历史区。

普通吃饭、出门、安慰、礼物、练习和反复表态通常不记录。愿望、梦境、猜测及尚未确认的计划不能当成已发生；“决定去救人”也不等于“已经救下人”。模型先判断重要性，程序再检查分类、主题、引文和来源；程序不能独立证明模型对“重大”的理解必然正确。

## 发给正文模型的内容

插件在正文生成前，等待分析模型选择与本轮有关的事件并归组。示例为虚构内容：

```text
<butterfly_continuity>
【持有钥匙改变进城条件】
原著情况：旅行者没有取得钥匙，只能绕道进城。
当前剧情：守卫已经把钥匙交给旅行者。
改变的前提：当前可以从城门通行，绕道的前提已经改变。
聊天依据：#12
</butterfly_continuity>
```

正文仍使用酒馆中原本配置的模型。资料以酒馆扩展提示的聊天内位置发送：深度 1、system 角色、不参与世界书扫描。扩展不创建额外聊天消息。

已发生、计划／约定、尚不确定会分开标明。当前已确立事实和人工修正优先，原作对照用于说明前提变化。发送候选只包含有资料引文支持的重大分歧。模型选择失败时会显示原因，并用已有的重大分歧生成简要对照；没有合格记录则不加入资料，正文正常生成。

## 参考资料与准确性

- 本版使用手动提供的参考资料，**不会自动联网，也不包含小说或 Wiki 数据库**。不会自动读取角色卡、世界书、其他聊天或电脑文件；分析输入来自当前批次、已有记录及已添加的参考资料。发送前筛选额外读取当前聊天最近 4 条消息。
- 模型需要提供聊天原句、资料编号和逐字引文。程序会检查引用是否确实存在、是否属于本轮提供的资料；模型不能通过编造来源列表给自己背书。
- 引用存在不等于结论一定正确，程序不能机械证明语义推论。请留意改编版本、故事阶段、转述、否定和角色猜测。资料类型会保留，Wiki 和时间线不会被标成原著片段。
- 缺少资料或来源冲突时，可能构成重大分歧的候选保留在「待核实」区，不计入正式分歧、不发送正文。补充资料后，撤销对应整理并重新分析；保存参考资料本身不会自动重算已有记录。
- 「修正」可改写当前记录；「锁定」优先保留该项，并阻止自动分析替换它。剧情发生后续变化时，请按需要解除旧锁定。锁定仍须满足重大分歧、来源引文和总发送预算要求。
- 「撤下」和「撤销最近一次整理」保留原始记录。编辑、删除、回档或切换回复后，内容校验不再一致的后续记录暂时停用；返回完全相同的分支可恢复。
- 修改参考资料后，新的核对会使用新资料。已经保存的对照保留当时的来源快照，不自动重算；需要纠正旧结论时，撤销对应整理并重新分析，或撤下错误记录。

## 从 0.2.0 更新

先导出记录并备份聊天，再替换扩展文件、强制刷新页面。聊天存储字段和模型设置字段保持不变，参考资料与旧记录保留。旧标准记录会折叠显示、暂不发送，也不会自动删除或自动声称通过新标准；需要重审时，撤销相应整理后按新标准重新分析。

## 数据保存与隐私

| 内容 | 保存位置 |
|---|---|
| API 地址、模型、参数 | 酒馆当前用户的扩展设置 |
| API 密钥 | 当前浏览器会话的 `sessionStorage`，按完整 API 基础地址隔离 |
| 世界线记录、参考资料、来源快照 | 当前聊天的 metadata，随聊天保存 |
| 「导出记录」 | 当前聊天的世界线记录和参考资料，不包含 API 密钥 |

密钥不会写入聊天或酒馆设置文件，刷新页面通常可保留，关闭浏览器会话后可能需要重新填写。同一酒馆页面里的其他脚本具备浏览器页面权限，请只安装可信扩展。远程使用酒馆时应通过 HTTPS 或可信隧道访问。

请求经过酒馆后端发往你填写的 API 地址。`localhost` 在这里指运行酒馆服务器的电脑。酒馆服务器自身的网络代理设置仍会影响连通性。原生 Anthropic Messages、Gemini / Vertex 原生接口和 Responses-only 接口不在本版支持范围，需使用服务提供的 Chat Completions 兼容入口。

## 容量和故障处理

- 每批最多 8 条消息、5.5 万字符，单条最多 5 万字符；按完整消息分批，超限会明确提示并保留旧记录。
- 最多 12 份参考资料，合计 4.5 万字符。建议只放当前阶段需要核对的材料。
- 整理时最多处理 200 条已有记录；筛选时最多 250 条候选，整体请求最多 30 万字符。超过上限会提示，不静默截断。
- 发给正文的差异资料默认最多 **6500 字符**，按完整事件组取舍；字符数不等于 token 数。
- 默认等待模型 180 秒，可改为 15–600 秒。超时、JSON 无法解析或引用不匹配时不覆盖旧记录，可调整模型参数后重试。
- 模型返回长度上限时，请提高输出 tokens 或减少参考资料。接口 HTTP 错误请检查地址、密钥、模型权限和服务状态。
- 点击「暂停此聊天」可停用该聊天的分析和发送；酒馆扩展管理器中禁用扩展会清理按钮、监听器和注入提示。

## 开发与验证

无运行时第三方依赖。Node.js 20 以上可运行：

```sh
npm test
```

测试覆盖聊天依据、分支回放、取消与切换、JSON 错误、来源伪造、独立密钥、API 参数和生成前拦截器。源码使用 `SillyTavern.getContext()`，清单要求酒馆 1.18；1.17 尚未验证。

0.3.0 的验证范围见 `CHANGELOG.md`。公开版与作者自用版是独立配置、独立存储的扩展，安装时请选择一份使用，避免重复整理或重复注入。不同服务的模型参数和输出质量需要使用者实际验证。
